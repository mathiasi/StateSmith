# Rust target spike

A quick, minimal Rust backend for StateSmith (release 0.22.2), built to see what generated Rust looks like and how it behaves.
It is not a mergeable backend: no upstream PR, issue or comment was made. Upstream tracking issue: StateSmith/StateSmith#475.

## Headline results

| Check | Result |
|---|---|
| `LightSm` example (hierarchy, guard, entry/exit actions, shallow history) | generates, builds with **0 rustc / 0 clippy warnings**, runs correctly (output below) |
| Generated module uses only `core` | yes: no `std`, `alloc`, `String`, `Vec`, `format!`, `println!` |
| `#![no_std]` staticlib for `riscv32imc-unknown-none-elf` | **builds, clippy clean**. LightSm demo fn: 528 B `.text`. The 174-state Spec2 machine builds too |
| Spec2 behaviour suite (`src/StateSmithTest/spec/2/`, same 46 tests every language runs) | **46 / 46 pass** |
| Existing tests | `AlgoTests` pass; other languages' committed outputs are byte-identical. Full suite: same 92 failures as the untouched base commit (environment issues, see below), nothing new fails |

## How it works

StateSmith's default algorithm (`Balanced2`) writes the whole machine as GIL, a C# subset. A per-language transpiler parses
that with Roslyn and prints it with a `CSharpSyntaxWalker`. The Rust target adds one more walker:

- `src/StateSmith/Output/Gil/Rust/RustGilVisitor.cs` (about 980 lines) translates GIL to one `.rs` module file.
- `src/StateSmith/Output/Gil/Rust/GilToRust.cs` writes `<snake_case_sm_name>.rs`.
- `src/StateSmith/Output/Gil/Rust/RustNameMangler.cs` sets the naming (see Decisions).
- Wiring: `TranspilerId.Rust`; a `TranspilerId.Rust` case in `AlgoTranspilerCustomizer` (Balanced2 only, like Java, Python and TS);
  `IRenderConfigRust` / `RenderConfigRustVars` (`Imports`, `VarsDerives`, `ImplCode`); `RustExpansionVarsPathProvider` (`self.vars.`);
  `RustAutoVarsParser`; DI registration in `SmRunner` and `DiServiceProvider`.
- One shared-algorithm fix: `AlgoBalanced1.OutputFuncStart` hard-coded `this.ROOT_enter();` instead of asking the name mangler.
  Every existing mangler returns `ROOT_enter`, so other languages' output doesn't change (confirmed by `AlgoTests` and the committed outputs).

Translation rules:

| GIL (C#) | Rust |
|---|---|
| nested `enum` | module-level `#[repr(u8)] #[derive(Clone, Copy, PartialEq, Eq, Debug, Default)] pub enum` (`#[default]` on the 0 variant, `u16` or `u32` repr if needed), plus `pub const <ENUM>_COUNT: usize` |
| nested `const int` | module-level `pub const NAME: i32` |
| nested `struct Vars` | module-level `pub struct Vars` + `impl Vars { pub const fn new() }` |
| state machine class | `pub struct Sm { pub state_id, pub vars }` + `impl Sm { ... }` + `impl Default` |
| constructor | `pub const fn new() -> Self` (fields given defaults: enums take their 0 variant, ints 0, bools false, structs `T::new()`) |
| instance method | `fn name(&mut self, ...)` (`pub` if public) |
| static method (`state_id_to_string` ...) | `pub const fn`, `string` becomes `&'static str` |
| `switch` / `case X:` / `default:` | `match` / `X => { ... }` / `_ => { ... }`. **The section-ending `break` is dropped**, because a `break` inside a `match` inside `exit_up_to_state_handler`'s `while` would exit the loop. Any other `break` inside a section is rejected with an error |
| non-exhaustive switch | adds `_ => {}` |
| `default:` when every enum variant has an arm | dropped. A `#[repr(u8)]` Rust enum can't hold an out-of-range value in safe code, so it would only be an unreachable pattern |
| `if (cond)`, `while (cond)` | `if cond`, `while cond` (parens stripped). `if (true) {}` becomes a plain block |
| `bool x = false;` | `let mut x: bool = false;` |
| `StateId.ROOT`, `this.x` | `StateId::ROOT`, `self.x` |
| `(int)x`, `new T()`, `x++;` | `(x as i32)`, `T::new()`, `x += 1;` |

## Generated code excerpt

From `src/test-misc/rust-light/src/light_sm.rs`, generated from `src/test-misc/rust-light/LightSm.plantuml`
(the kickoff `LightSm`, plus an exit action on `ON_GROUP` and a `[H]` history vertex). This example uses K&R braces
(`settings.style` with `BracesOnNewLines => false`). Spec2 uses the default style (braces on new lines), and both compile.

```rust
// Autogenerated with StateSmith.
// Algorithm: Balanced2. See https://github.com/StateSmith/StateSmith/wiki/Algorithms

#![allow(non_camel_case_types, non_snake_case, non_upper_case_globals, dead_code, unreachable_code, unused_mut, unused_assignments, unused_variables, unused_parens, clippy::needless_return, clippy::single_match, clippy::upper_case_acronyms)]

// Generated by StateSmith (Rust spike). Do not edit.
use crate::light::Light;

#[repr(u8)]
#[derive(Clone, Copy, PartialEq, Eq, Debug, Default)]
pub enum EventId {
    #[default]
    DIM = 0,
    INC = 1,
    OFF = 2,
}
pub const EVENT_ID_COUNT: usize = 3;
// ... StateId, subtree-end consts ...

#[repr(u8)]
#[derive(Clone, Copy, PartialEq, Eq, Debug, Default)]
pub enum ON_GROUP_HistoryId {
    #[default]
    ON1 = 0, // default transition
    ON2 = 1,
}
pub const ON_GROUP_HISTORY_ID_COUNT: usize = 2;

// State machine variables. Can be used for inputs, outputs, user variables...
pub struct Vars {
    pub ON_GROUP_history: ON_GROUP_HistoryId,
    pub count: u8,
    pub light: Light,
    pub group_exits: u16,
}

impl Vars {
    pub const fn new() -> Self {
        Self {
            ON_GROUP_history: ON_GROUP_HistoryId::ON1,
            count: 0,
            light: Light::new(),
            group_exits: 0,
        }
    }
}

// Generated state machine
pub struct LightSm {
    // Used internally by state machine. Feel free to inspect, but don't modify.
    pub state_id: StateId,

    // Variables. Can be used for inputs, outputs, user variables...
    pub vars: Vars,
}

impl LightSm {
    // State machine constructor. Must be called before start or dispatch event functions. Not thread safe.
    pub const fn new() -> Self {
        Self {
            state_id: StateId::ROOT,
            vars: Vars::new(),
        }
    }

    // Dispatches an event to the state machine. Not thread safe.
    pub fn dispatch_event(&mut self, event_id: EventId) {
        match self.state_id {
            // STATE: LightSm
            StateId::ROOT => {
                // No events handled by this state (or its ancestors).
            }

            // STATE: OFF
            StateId::OFF => {
                match event_id {
                    EventId::INC => { self.off_inc(); }
                    _ => {}
                }
            }
            // ...
            // STATE: ON2
            StateId::ON2 => {
                match event_id {
                    EventId::INC => { self.on2_inc(); }
                    EventId::DIM => { self.on2_dim(); }
                    EventId::OFF => { self.on_group_off(); } // First ancestor handler for this event
                }
            }
        }
    }

    fn exit_up_to_state_handler(&mut self, desired_state: StateId) {
        while self.state_id != desired_state {
            match self.state_id {
                StateId::OFF => { self.off_exit(); }
                StateId::ON_GROUP => { self.on_group_exit(); }
                StateId::ON1 => { self.on1_exit(); }
                StateId::ON2 => { self.on2_exit(); }
                _ => { return; }  // Just to be safe. Prevents infinite loop if state ID memory is somehow corrupted.
            }
        }
    }

    fn off_inc(&mut self) {
        // OFF behavior
        // uml: INC TransitionTo(ON_GROUP.<History>)
        {
            self.off_exit();
            self.on_group_enter();
            // ON_GROUP.<History> behavior
            // uml: [$gil(this.vars.ON_GROUP_history == ON_GROUP_HistoryId.ON2)] TransitionTo(ON2)
            if self.vars.ON_GROUP_history == ON_GROUP_HistoryId::ON2 {
                self.on2_enter();
                return;
            } // end of behavior for ON_GROUP.<History>

            // ON_GROUP.<History> behavior
            // uml: else TransitionTo(ON1)
            {
                self.on1_enter();
                return;
            } // end of behavior for ON_GROUP.<History>
        } // end of behavior for OFF
    }

    fn on_group_exit(&mut self) {
        // ON_GROUP behavior
        // uml: exit / { record_group_exit(); }
        {
            // Step 1: execute action `record_group_exit();`
            self.record_group_exit();
        } // end of behavior for ON_GROUP

        self.state_id = StateId::ROOT;
    }

    fn on2_inc(&mut self) {
        // ON2 behavior
        // uml: 1. INC / { count += 1; }
        {
            self.vars.count += 1;
        } // end of behavior for ON2

        // ON2 behavior
        // uml: 2. INC [count >= 3] TransitionTo(OFF)
        if self.vars.count >= 3 {
            self.exit_up_to_state_handler(StateId::ROOT);
            self.off_enter();
            return;
        } // end of behavior for ON2
    }

    pub const fn state_id_to_string(id: StateId) -> &'static str {
        match id {
            StateId::ROOT => { return "ROOT"; }
            StateId::OFF => { return "OFF"; }
            StateId::ON_GROUP => { return "ON_GROUP"; }
            StateId::ON1 => { return "ON1"; }
            StateId::ON2 => { return "ON2"; }
        }
    }
}

impl Default for LightSm {
    fn default() -> Self {
        Self::new()
    }
}
```

(The `// Step N:` comments are trimmed here. The real file keeps all of GIL's comments.)

## Example output

`cd src/test-misc/rust-light && cargo run` (`src/main.rs` dispatches the events and prints the state after each):

```
start      -> state: OFF      light: Off    count: 0 group_exits: 0
INC        -> state: ON1      light: Blue   count: 0 group_exits: 0
INC        -> state: ON2      light: Yellow count: 0 group_exits: 0
INC        -> state: ON2      light: Yellow count: 1 group_exits: 0
INC        -> state: ON2      light: Yellow count: 2 group_exits: 0
INC        -> state: OFF      light: Off    count: 3 group_exits: 1
INC        -> state: ON2      light: Yellow count: 0 group_exits: 1
DIM        -> state: ON1      light: Blue   count: 0 group_exits: 1
OFF        -> state: OFF      light: Off    count: 0 group_exits: 2
INC        -> state: ON1      light: Blue   count: 0 group_exits: 2
DIM        -> state: OFF      light: Off    count: 0 group_exits: 3
```

What each step shows:
- the `[count >= 3]` guard fires on the third INC.
- the `ON_GROUP` exit action runs on every way out of the group (guard, `OFF` handled by the parent, `DIM` from ON1).
- history: INC from OFF returns to ON2, and later to ON1, whichever was active last.
- ON2's entry action resets `count`.

## no_std build

`src/test-misc/rust-light-nostd/` is a `#![no_std]`, `panic = "abort"`, `staticlib` crate. It pulls in the generated
`light_sm.rs` and the user's `light.rs` via `#[path]`, and also the large generated `spec2_sm.rs`, with `trace()` as a no-op.

## Spec2

`src/StateSmithTest/spec/2/Rust/` follows `spec/2/Python/`:
- the fixture generates `src/test-misc/rust-spec2/src/spec2_sm.rs` (13.5k lines, 174 states, using the default brace style).
- the fixture rewrites `x++` in the diagram's C-like code to `x += 1`. Nothing else in the diagram needed changing.
- the fixture runs `cargo build --release` once, and each test runs the binary with the event list.
- the harness is `main.rs` + `printer.rs` (std, for printing only). The generated module still only uses `core`.


Those 46 tests cover do events (and consuming them), behaviour ordering, parent/child, local, external and alias transitions,
shallow and deep history, choice points, entry and exit points, variables, auto-vars and meta expansions.

## Decisions

**Naming** (`RustNameMangler`). This is deliberately conservative:
- state handler functions are `snake_case` (`on_group_exit`, `t7__h1__on_exit`). Lower-casing can't collide, because state names are already unique ignoring case.
- the module file is `snake_case` (`light_sm.rs`).
- enum variants stay `SCREAMING_CASE` (`StateId::ON_GROUP`), like C, C# and Python. They map 1:1 to the diagram and re-casing can't introduce collisions.
- history fields and types keep StateSmith's names (`ON_GROUP_history: ON_GROUP_HistoryId`). Every other target keeps them, and the shared Spec2 expectations and `$gil(...)` history code use them literally. My first attempt lower-cased the field, and it failed 8 history tests on naming alone.
- because of the last two points, the file needs `#![allow(non_camel_case_types, non_snake_case, non_upper_case_globals)]`.

Truly idiomatic names (`StateId::OnGroup`, `OnGroupHistoryId`) would need collision handling (`A_B` and `AB_` both become `AB`). Spec2's expectations would also have to stop hard-coding mangled names.

**Other allowed lints**, all of them benign for generated code:
- `dead_code`: unused helper fns and consts.
- `unreachable_code`: GIL emits `return;` and then comments or code after it.
- `unused_mut`, `unused_assignments` and `unused_variables`: GIL's `consume_event` local, which some `do` handlers declare and never read, and diagram code that sets it twice.
- `unused_parens`: guard code from the user.
- `clippy::needless_return`, `clippy::single_match`, `clippy::upper_case_acronyms`: style only.

The output is not rustfmt-clean (blank lines carry indentation, and short arms are written `X => { self.f(); }`). `rustfmt` on it works, and the result still compiles.

**Vars initialisation: `const fn new()` works.** User variables are raw target code, so the Rust target asks for one
`name: Type = const_initializer,` per line, for example:

```
count: u8 = 0,
light: Light = Light::new(),
```

The visitor splits each line into a struct field and an initialiser. That gives a `const fn new()` for both `Vars` and the machine, which matters on embedded: a machine can be a `static` and needs no lazy init.
- a line without `= init` falls back to `Default::default()`, and `new()` then stops being `const`.
- GIL's own fields (history vars, `state_id`) default to their enum's 0 variant.
- `RustAutoVarsParser` reads the same syntax for `AutoExpandedVars`.

**How user code reaches the outside world.** All three options were weighed. The spike demonstrates the first two, side by side, in the LightSm example:

1. **Owned fields, demonstrated.** `Vars` holds user types, for example `light: Light` (a stand-in for a HAL driver), and diagram code calls `self.vars.light.blue()` through expansions. This is simple, `const`, no_std and zero-cost. Its limit is that the type must be concrete: the generator doesn't emit generics, so `Vars` can't be `Vars<P: OutputPin>`.
2. **A user `impl` block, demonstrated.** Rust lets any module of the same crate add an inherent `impl LightSm { fn record_group_exit(&mut self) {...} }`. `light.rs` does this, and the diagram calls `self.record_group_exit()`. The generator needs no knowledge of it, and the method has full `&mut self` access. The catch is that it only works inside the crate that contains the generated module, which is the normal setup anyway.
3. **A trait, not done.** This would be `pub struct LightSm<H: LightSmHooks>`, with diagram code calling `self.hooks.light_blue()`. It's the most testable option (mock hooks on the host, real ones on the device), and probably the right default for a device-plus-TypeScript setup. It needs generator support for generic parameters on the struct and its `impl`s, plus a way to declare the trait (user-written, or generated from the diagram's function calls). With `H` as a generic, a `const fn new(hooks: H)` is still possible.

`IRenderConfigRust.ImplCode` also exists for pasting code into the generated `impl`, like `ClassCode` in other targets.

**Other decisions**:
- `state_id` and `vars` are `pub`, matching the other targets.
- `#[repr(u8)]` is on every enum, so they're FFI and BLE friendly. A hand-written `transmute` from `u8` works, but it's `unsafe`, and the Spec2 harness and no_std demo both need one.
- static helpers are `const fn`.
- a `Default` impl calls `new()`.
- the GIL `default:` arm is dropped when a match is already exhaustive.

## Problems hit

- **Found later, by the Manetta example (`src/test-misc/manetta-example/`):** `RustAutoVarsParser` used `StringUtils.RemoveCCodeComments`, which also eats the newline after a `//` comment. Any auto-var declared on the line after a commented one was silently not expanded. It's fixed now; comments are stripped line by line.

- **`this.ROOT_enter()` was hard-coded** in the shared Balanced1/2 start function. Any mangler that renames state handlers broke Roslyn's view of the GIL. I fixed it to ask the mangler, which gives identical output for every existing target.
- **`SmRunnerInternal` overwrites `OutputInfo.BaseFileName` with `sm.Name`**, so `NameMangler.BaseFileName` is ignored. `GilToRust` takes the file name from the mangler directly. Changing the shared behaviour would also rename other targets' `.md` and `.json` sidecars.
- **`CodeStyleSettings.BracesOnNewLines` is a get-only virtual.** A transpiler customizer can't flip it; the user has to subclass `CodeStyleSettings` and set `settings.style`. In K&R mode the core GIL writer also:
  - puts a bare block's `{` at column 1 after a comment line;
  - still writes guard `if`s with the brace on the next line.

  The visitor fixes both up. Python's transpiler documents that K&R breaks it.
- **The `break` handling needed care**: my first guard against "`break` in the middle of a section" also caught the `break`s of nested switches. It now stops at the nearest enclosing switch section or loop.
- **Spec2 trace text bakes in mangled names**, as described under Naming.
- **Diagram code is target code.** Spec2's C-like `count++` had to be rewritten for Rust, the same way the Python fixture rewrites code.
- **The TOML reflection tripwire.** `TomlConfigTest_335.TestReflectionMapping` asserts the number of `TranspilerId`s, so that a new language gets TOML tests. TOML was out of scope, so I bumped the count and left a comment saying `[RenderConfig.Rust]` isn't covered yet.
- **Environment.** None of these are code problems:
  - .NET 9 couldn't be downloaded here (`builds.dotnet.microsoft.com` is blocked by the network policy), so I used the .NET 10 SDK from Ubuntu's archive and ran the net9.0 tests with `DOTNET_ROLL_FORWARD=Major`.
  - the container's inotify instance limit (128) failed hundreds of tests until I raised it (`sysctl fs.inotify.max_user_instances=8192`).
  - the untouched base commit fails 92 tests here, all Java and TypeScript Spec2. The proxy's `JAVA_TOOL_OPTIONS` banner on stderr breaks Java, and npm's engine warning (Node 22 installed, 24 required) breaks TypeScript. The branch fails exactly the same 92 and nothing else.

## What a full upstream backend would still need

Roughly, from most to least important:
1. **A design agreement with the maintainer.** The maintainer asked for a manual translation and an agreed design first. This spike can serve as that translation, but these questions are still open:
   - naming;
   - the var-declaration syntax;
   - owned fields vs `impl` vs trait (or all three);
   - `pub` fields vs getters;
   - `i32` vs `u8`/`StateId` for subtree consts.
2. **Hooks via a trait or generic parameter** (option 3 above). This needs the generator to emit `<H: Trait>` on the struct and its `impl`s.
3. **Idiomatic naming** (CamelCase variants and types) with collision detection, which drops most of `#![allow]`. Spec2 expectations would also have to stop hard-coding mangled names.
4. **Event and state conversion helpers**: `TryFrom<u8>` for `EventId` and `StateId`, so callers don't need `transmute`. This matters for BLE or FFI input.
5. **Cleaner output**:
   - no trailing whitespace;
   - expression-style arms (`X => self.f(),`) and to-string fns;
   - no `return;` at the end of blocks;
   - optionally, running rustfmt.

   This is what would let the remaining clippy allows go.
6. **The GIL constructs the spike rejects with an error** but other diagrams or settings might produce:
   - multiple labels per switch section;
   - constructors with statements or parameters;
   - `null`, nullable types and function pointers (needed for Balanced1; Rust could use `fn(&mut Self)`);
   - `if` or `while` without braces;
   - C# string escapes that differ from Rust (`\u{...}`, verbatim strings).

   `if (true)` handling exists but was not exercised (the Rust target doesn't enable `useIfTrueIfNoGuard`).
7. **Product surface**:
   - TOML `[RenderConfig.Rust]` support and tests (the tripwire above);
   - `ss.cli create` templates;
   - `$CONFIG` / diagram-embedded settings;
   - docs and wiki pages;
   - a Rust page in the settings reference.
8. **CI**:
   - cargo in the test images;
   - the Spec2 Rust suite;
   - `AlgoTests` outputs compiled with `rustc`, not just generated;
   - a `no_std` cross-build job;
   - clippy with `-D warnings`.
9. **Tracing and simulator** parity, plus any other spec suites other targets run.

## Reproduce

Setup: .NET SDK (net9 runtime, or SDK 10 with `DOTNET_ROLL_FORWARD=Major`), Rust stable, and `rustup target add riscv32imc-unknown-none-elf`.

```
cd src/StateSmithTest
dotnet test --filter "FullyQualifiedName~RustLightSmGenTests"      # regenerates light_sm.rs and runs `cargo run`
dotnet test --filter "FullyQualifiedName~Spec.Spec2.Rust"          # Spec2: 46 tests
dotnet test --filter "FullyQualifiedName~StateSmithTest.Output.Algos.AlgoTests"

cd ../test-misc/rust-light && cargo run
cd ../rust-light-nostd && cargo build --release --target riscv32imc-unknown-none-elf
```
